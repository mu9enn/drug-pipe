## 1. 历史 pretrained 成绩的解释需要收紧

应区分两类历史结果：

- 汇报中的原版 9B MS-1 accuracy=0.82，来自 `dsh_qwen35_original_ms1_ms2_full_20260820`。该运行采用 standard preset、旧技能工作区、83 题；总体完成 57/83，26 题失败或缺失，7 条答案来自 artifact 回收。数字是旧协议下的记录，不能直接与后续 Read-first / skill-native SFT 作公平比较，也不能凭这些问题断言 0.82 一定虚高或一定虚低。
- 9 月 7 日 r3 pretrained 八组矩阵（9B、27B、35B-A3B、122B-A10B × flat/hierarchy）已经逐组写入 `SETTING_INVALID.json`，明确 `official_score_publishable=false`。这不是仅仅“环境略有差别”，而是已确认评测设置存在错误。不能换一个 parser 离线重算后，将其当成新规范下的正式成绩。

## 2. 具体问题与修复

| 问题 | 为什么影响结论 | 已完成的修复 |
|---|---|---|
| MS-1 第 36–50 题误用了 AC 的 `answer_smiles` 契约 | 单选 PF 仍属于 MS-1，不应因只选一个分子而更换字段；题面、训练标签和评分入口可能相互矛盾 | 全部 PF 使用 `selected_smiles` 数组；单选恰好一项。数量约束进入冻结题单，不再依靠 runner 行号补丁 |
| XML、裸文本、JSON 及正文 SMILES 回收路径并存 | 有的答案被漏提取，有的违规输出经程序“救回”；格式能力与科学得分混在一起 | 题面、采集、清洗、SFT、harness 共用 `output_contracts.py`；正式评测只接受完整最终 JSON，单独报告 JSON 合法率、题目约束合规率、科学指标和故障率 |
| DSH coding-agent system 内容混入 | 实际给模型的信息不是预期的完整实验提示词 | 专用 preset 使用完整统一 system；system 末尾只放通用规则，字段与数量要求放题面 |
| Web、goal、todo、job、subagent 等额外工具进入评测 | 可用行动空间和工具描述不同，无法只归因于模型权重 | 专用评测工具固定为 81 个 MolClaw + 7 个本地/harness 工具，共 88；训练同步替换 105-tool snapshot，并对比完整 schema |
| hierarchy 把旧 system 当作 prompt prefix；后续又发现嵌套 skill 不可发现 | 不仅增加了方法论知识，还改变系统指令，甚至实际上没暴露预期技能 | 规范 `.agents/skills` 发布布局与 catalog；52 L1 和 68 层级技能分别作为明确环境，只在同一环境内比较原版和 SFT |
| r3 记录 temperature=0，但未落实到请求或服务默认值 | 配置声明不能证明实际执行是 greedy | 固定并记录实际请求采样配置；统一 native thinking、262144 上下文和 16384 单次响应上限。旧 r3 manifest 还记录了 thinking=false、65536 上下文，不能与新协议混用 |
| MS-2 排除四题，只跑 33 题 | 测试子集改变，旧排除还漏掉反向 AC 同源题 | 固定上游 50/37/25；默认测 MS-1/MS-2 全部 87 题，全部 112 题参与训练隔离。污染从训练端移除，不继续删测试题 |
| 未完成、基础设施失败、格式失败混杂 | 低分可能来自执行/协议问题，不能全部解释为科学能力不足 | 全部选定题进入分母；仅基础设施故障最多重试两次；缺题、未完成、未解决基础设施故障或协议不匹配不能成为正式完整结果 |

历史汇总已存在“全部选定题进入分母”的规则，不能笼统声称过去都只统计成功样本。本次主要补齐失败分类、发布资格和协议一致性，保留上游评分数学定义。空 PF 选择可能是正确科学答案，也不应与没有最终回答混为一谈。

仅离线重评分不能修复已改变的 system、工具、技能信息、上下文或采样行为。新协议的有效模型对比仍需未来重新运行。两题 smoke 的 `publishable` 也只描述其选定子集，不能当成完整 87 题成绩。

## 3. 512 → 596 的数据变化应补入原汇报

旧 602 条视图的候选/排序异常计数属于协议违规，并不等于同样数量的科学错误。进一步回溯后曾发布 512 条保守训练集，87 条待恢复隔离分别为 AC 6、PF 5、VS 76。

本窗口随后明确：有推理和工具证据的样本可以较宽松地恢复，不为追求完美标签大量丢弃；中断且没有结论的轨迹直接丢弃。最终恢复 84 条：AC 5、PF 4、VS 75。剩下的是 1 条 PF 明确引用预期答案，以及 AC、VS 各 1 条无结论中断。

最终口径为：605 条母数据 − 3 条测试同源 − 1 条答案引用 − 2 条无结论中断 = 599 条语义轨迹；再排除 3 条完整超长 KG，得到 596 条训练轨迹，而不是原先预估的 598 条。

其中 51 条 VS 含未确定优先级的尾部：有实测/报告依据的部分先排序，其余候选进入明确未确定的尾部，字典序只用于并列顺序。没有使用测试标准答案补标签，也没有把未知候选声称为经过科学验证的完整亲和力排序。这批数据属于可训练的证据重建标签，不是全部未经改写的 teacher 原始终答，也不是 596 条科学金标准。

## 4. 一次性修数据之外，要求进入了常规 data-pipe

- raw 阶段：公开题目契约、测试隔离、L1 场景与限定工具；Claude/DSH 都保留。执行目录与私有归档分开，工作区只写公开 question.json，避免从祖先目录意外读到标准答案。
- Python 阶段：保留消息/调用绑定、完整结构化科学结果；明确选择与唯一立体化学身份映射可直接恢复；不能确定的进入 LLM，不提前一律丢弃。
- skill 适配：移到 LLM 之前。修复“失败 skill observation 被改成成功”的问题，真实错误和后续恢复保留；不再生成 legacy note 一类处理话术。
- LLM 阶段：负责推理表达和待恢复终答，工具事实保持不变，不能把未来观察写入早期决策。终答和结构有效时，即使润色失败也保留；措辞质量不足只记提示。
- 发布阶段：共享契约复验、实际 tokenizer 和 qwen3_5 loss mask、整条长度门控、哈希 manifest 接入常规入口。审计等级、恢复方法、事件引用和计数留在侧文件，不进入训练监督文本。

完整逐项对照见 [DATA_PIPE_REGULAR_CLEANING.md](DATA_PIPE_REGULAR_CLEANING.md)。
