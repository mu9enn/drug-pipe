## 审计结论

判定为 **B. Drug-Pipe 确实存在显著 multi-tool-per-thought / per-response action**。

- 7,846 个带工具的原始 assistant response 中，2,330 个包含至少 2 个 tool calls，占 **29.70%**。

- 2,312/2,330（99.23%）随后收到了完整结果批次；18 个 response 因中断/缺失只收到部分结果。
- 当前 mol canonical SFT 中仍有 **30.76%** 的 tool decisions 是 multi-tool。
- 当前 full canonical SFT 中仍有 **21.96%** 的 tool decisions 是 multi-tool。

所以自然语义并不是：

```text

```

而是两者都有，且 multi-tool 不是可忽略 edge case。典型 multi 语义是：同时计算多组分子描述符、同时查询多个蛋白结构、批量 docking 多个 ligand；这些调用不依赖彼此的 observation。

## 4. Thought 在当前 ToolRL 中如何训练

当前两个 run 都明确使用 hierarchical reward：

- [full resolved config](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/outputs/slime_drug_agent_runs/Qwen3.5-9B_v5_full_toolrl_klfix_20260817_142744/resolved_config.env:8)
- [mol resolved config](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/outputs/slime_drug_agent_runs/Qwen3.5-9B_v5_mol_toolrl_klfix_20260817_142744/resolved_config.env:8)

实际 loss path 是：

```text
history-only prompt
→ SGLang 生成整个 response
→ 全 response token mask=1
→ hierarchical sequence reward
→ group mean/std advantage
→ advantage 广播到全部 response tokens
→ masked policy loss
```

证据：

1. `sample.response` 追加模型生成的整个 text，response token 数同步增加：[sglang_rollout.py](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/slime/rollout/sglang_rollout.py:206)。因此模型若生成 `<thought>...<tool_call>...`，整段都是 action。

2. 正常 rollout 没有特殊 mask 时，所有 response tokens 都设为 1：[ray/rollout.py](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/slime/ray/rollout.py:698)。thought tokens 与 tool-call tokens 都在 policy loss mask 内。

3. reward 先做组内去均值，可选除以标准差：[ray/rollout.py](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/slime/ray/rollout.py:637)。

4. GRPO 把每条 sequence 的标量 reward 广播成与 response token 序列同形的 return：[ppo_utils.py](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/slime/utils/ppo_utils.py:306)。thought 和 tool-call token 得到同一个 sequence-level advantage。

5. policy loss 从 response log-prob、advantage 和 response mask 计算并归约：[loss.py](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/slime/backends/megatron_utils/loss.py:805)、[950–973](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/slime/backends/megatron_utils/loss.py:950)。

6. reward 从模型完整 response 中解析 calls，但 gold 只抽 `target_tool_calls`：[molclaw_reward.py](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/drug_agent/toolrl/molclaw_reward.py:72)、[848–887](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/drug_agent/toolrl/molclaw_reward.py:848)。

7. hierarchical reward 只检查有效 envelope、tool set、required/critical/configurable arguments：[735–814](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/drug_agent/toolrl/molclaw_reward.py:735)。

8. runtime grammar 允许没有 thought 的 `tool_call` 或 `final_answer`；thought 是 optional：[react_protocol.py](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/drug_agent/protocol/react_protocol.py:434)。空的显式 `<thought></thought>` 会触发格式错误，但完全不写 thought 不会受罚。

结论：

| 问题 | 当前 ToolRL |
|---|---|
| rollout action 包含 thought + tool call 吗 | 包含模型实际生成的整段 response |
| thought tokens 在 loss mask 内吗 | 是 |
| advantage 广播给 thought 和 call tokens 吗 | 是 |
| teacher thought 内容进入 reward 吗 | 否 |
| thought 语义有直接奖励吗 | 否 |
| thought 存在性有直接奖励吗 | 否；thought 可省略 |
| thought 长度有直接奖励吗 | 否 |
| teacher thought 是当前 RL supervised target 吗 | 否 |

所以当前 ToolRL 中 thought 的准确定位是：

> **policy-generated tokens，被 sequence-level advantage 间接更新；不是 reward-scored semantic target，也不是当前 RL 阶段的 teacher-forced supervised target。**

但在之前的 SFT 阶段，source builder 把整段 assistant message 标为 `step_loss_mask=1`：[react_builder.py](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/data-pipe/pipeline/cleaning/react_builder.py:645)，Qwen3.5 loss mask 会覆盖 assistant content：[mask_utils.py](/home/sunxiangyu/slime_sxy/group-space/sunxiangyu/drug-pipe/slime-wd/slime/slime/utils/mask_utils.py:127)。因此 teacher thought 曾在 SFT 阶段被监督，但不在当前 ToolRL reward 中被语义评分。

- 只看 3,518 个 tool-action steps：1,695/3,518 = **48.18%**

因此官方 multi-tool 绝不是少数 edge case，接近一半的工具 action 都是 multi-call。

## 最终 decision

**B. Drug-Pipe 确实有显著 multi-tool-per-step。**

真实语义主要是可独立并行的属性计算、结构检索、批量 docking 和多候选评估。它们在同一个 Claude assistant response 中一次决定，所有调用先发出，之后才成批返回 observations。

当前 ToolRL converter 对 retained decision boundary 是忠实的：

- 没有把 observation 两侧的 calls 合并；
- 没有把原始 multi-tool response 拆成多个 decisions；
- per-decision call cardinality 保持；
- 与官方的主要差别是 serialization：Drug-Pipe 使用多个相邻 `<tool_call>` blocks，官方 canonical grammar 使用一个 block 内多行 JSON。

真正需要单独注意的是更早的 source builder：它过滤了 unsupported calls/observations，并可能压接其周围的 thought prose；但它没有制造当前的 multi-call decisions。

| 选择 | 含义 | 与原始 Drug-Pipe 数据 fidelity | 与 ToolRL paper fidelity |
|---|---|---|---|
| 保持 Drug-Pipe single-tool step grammar | 强制把每个 call 变成独立 action，即使中间没有 observation | **低**：会拆开真实 parallel batches | 中低：只覆盖官方 action space 的子集 |
| 改成 ToolRL canonical multi-tool grammar | 保持一个原始 response 为一个 decision；multi calls 放入一个 canonical block | **高**，前提是不插入虚构 observation | **高** |
| 支持两种 grammar | single response 可单 call；真实 batched response 可 multi call；parser 接受两种 serialization | **最高** | **高/兼容性最好** |

本次仅做了读取、解析和内存统计，没有修改任何文件、代码、checkpoint 或运行状态，也没有干扰当前 v5 full/mol run。
